# TrendCrafter AI 素材库 · 基于历史素材数据资产的 AI 供给决策系统

[![test](https://github.com/Han1108323/AI-Marketing-Material-Library/actions/workflows/ci.yml/badge.svg)](https://github.com/Han1108323/AI-Marketing-Material-Library/actions/workflows/ci.yml)

> 让营销素材生产从"拍脑袋做图"走向**数据驱动供给**。
> 核心逻辑不是"能不能生成一张图"，而是"**该不该做 + 怎么做最优**"：先判断素材库里有没有值得复用的高转化资产，再决定复用 / 微调 / 生成。
>
> 感知 → 认知 → 决策 → 执行 → 反馈，5 层 AI 闭环。

## 🎯 产品定位差异化（Positioning）

| 维度 | 传统设计 / AI 绘画工具（PS、Midjourney、SD） | **TrendCrafter AI 供给决策系统** |
|------|------------------------------------------|--------------------------------|
| 核心逻辑 | **"能不能做"** — 关注图像生成的技术可行性与美学表现 | **"该不该做 + 怎么做最优"** — 关注营销素材的**业务价值与投放效果** |
| 决策方式 | 依赖人工经验，"拍脑袋"做图；效果全靠猜 | **数据驱动决策，预测 CTR 指导生产** |
| 资产复用 | 重复劳动多，资产复用率低（约 10%） | **智能检索 + 智能微调，复用历史成功经验** |
| 学习与进化 | 无数据闭环，每次从零开始 | **全链路闭环，每一次投放都让决策模型更聪明** |

## 🩹 业务痛点：营销素材生产的三大核心矛盾

| 矛盾编号 | 矛盾名称 | 具体表现 |
|---------|---------|---------|
| **Conflict 01** | **资源浪费 · 资产隐形** | 企业积累海量历史素材，但缺乏有效标签体系，运营如同大海捞针。找不到只能重做，复用率仅约 10%。 |
| **Conflict 02** | **高昂试错 · 经验难沉淀** | 高转化素材的成功经验（配色、构图、文案）无法被系统化提取复用。新素材生产缺乏数据指导，"投放后"才能验证效果，资金浪费在无效广告上。 |
| **Conflict 03** | **生产瓶颈 · 需求碎片化** | 营销场景高度碎片化（节日、人群、渠道），改字换背景等微调需求量巨大；设计资源有限，做图成本高，难以实现规模化高质量供给。 |

## 🧠 核心决策逻辑：首创 "3R" 供给决策矩阵

TrendCrafter 改变了素材管理与生产模式，首创基于 CTR 预测的 **3R 决策矩阵**：

```
        相关度 & CTR 预估高  ────────────────────  相关度 & CTR 预估低
                │                                               │
                ▼                                               ▼
   ┌─────────────────────────┐                    ┌─────────────────────────────┐
   │   ✅ REUSE · 直接复用    │                    │  ⚠️ GENERATE · RAG 参考生成  │
   │   高转化素材直接下载使用 │                    │  高分视觉基因作为风格参考，   │
   │   生产边际成本趋近于 0   │                    │  结合新需求生成新素材         │
   └─────────────────────────┘                    └─────────────────────────────┘
                  \                                 /
                   \                               /
                    \                             /
                     ▼                           ▼
               ┌────────────────────────────────────┐
               │   🎯 FISSION · 智能微调与裂变       │
               │   素材基础良好 → 保留构图 + 针对本   │
               │   次人群/节点裂变（改文案/配色/节日） │
               └────────────────────────────────────┘
```

## 🔄 四大业务流程（PROCESS 01-04）

> **主线**：从非结构化散件文件 → 结构化数据资产 → 数据驱动供给决策。

| 流程编号 | 流程名称 | 阶段步骤 | 业务目标 |
|---------|---------|---------|---------|
| **PROCESS 01** | **素材入库与自动打标 Ingestion & Tagging** | 入库前 → 入库中 → 入库完成 → 数据资产沉淀 | 从非结构化文件（散图/压缩包/链接）**质变**为结构化可检索资产：OCR 提取文字 → 多模态视觉识别品类/风格/人群 → 自动标签置信度 → 向量化入库。 |
| **PROCESS 02** | **智能检索与供给决策 Search & Supply Decision** | 检索前 → 检索中 → 检索完成 → 决策建议 | 输入"618美妆红色主图 年轻女性" → 关键词 + 向量 + CTR 预估推理三重召回 → 按综合得分排序 → **给出 Agent 供给决策建议（复用/微调/生成）**。 |
| **PROCESS 03** | **智能微调 FISSION Smart Fine-tuning** | 微调前 → 确认修改范围 → 微调完成 | 选中一张高分素材 → 描述改动（节日氛围、价格文案、背景配色、人群替换）→ 参数化裂变 / 风格迁移 / 排版重绘 → **批量生成 3-8 张风格一致的变体**，成本比重做下降 60%。 |
| **PROCESS 04** | **RAG 智能生图 Retrieval-Augmented Generation** | 生图输入 → 生图完成 | 选择 3 张喜欢的高 CTR 风格素材作为参考 → 填写新需求 → 系统 RAG 参考这些视觉基因 + 文案模板 → 生成新品图，保证风格一致性与 CTR 遗传。 |

## 💰 总结与价值落地（SUMMARY）

### 核心价值（数据实证）

| 指标 | 改善幅度 | 说明 |
|------|---------|------|
| **找图 + 生产效率** | **30×** 提升 | 检索毫秒级返回 + 微调替代 60% 从零设计 |
| **素材生产成本** | **下降 60%** | 高 CTR 图直接复用（~30%）+ FISSION 微调（~60%），仅 ~10% 走全新生图 |
| **素材资产复用率** | **10% → 30%** | 结构化标签 + 推理检索 + CTR 预测召回 |
| **预测 CTR 相关性** | **持续进化** | 每一次投放报表回流 → L3 决策模型训练 → 增长飞轮 |

### 增长飞轮

> 随着更多素材投放，回流的 CTR 数据将持续训练 **L3 供给决策模型**，使 AI 越来越懂「**什么样的图能在特定品类 / 渠道 / 人群包真正跑量**」。

### Product Roadmap

| 阶段 | 里程碑 |
|------|--------|
| **Q1** | MVP 版本上线：核心检索 + FISSION 智能微调能力（当前已实现） |
| **Q2** | 投放数据自动化闭环：API 打通主流媒体（直通车 / 引力魔方 / 巨量千川）投放报表自动回传 |
| **Q3** | 智能推荐引擎：基于人群包 + 渠道自动生成最优素材组 / 计划 |

## 🚀 快速部署

### 🟢 路径一：快速预览版（零配置，3 分钟跑通核心链路）

无需任何 API Key，即可本地验证供给决策、素材检索和 CTR 看板：

```bash
./setup.sh portfolio
./run.sh portfolio
```

启动后按以下路径验证核心链路：
1. 「智能检索与供给决策」输入「双11美妆红色促销」→ 查看三重召回结果 + Agent 供给决策建议（3R 矩阵分流）
2. 「CTR 决策看板」查看行业样本预测 CTR 与真实 CTR 的交互散点图与偏差分析

真实智能微调依赖 DashScope，不以本地假图代替模型结果；请使用下方完整版本。

### 🟡 路径二：完整版本地部署（含登录权限 / 用户体系 / 商家配置）

完整账号体系与白名单准入机制 / 三角色分级 / 数据隔离逻辑详见 `src/auth.py` 与 `PRODUCT_LOGIC.md`「账号与权限体系」章节。

```bash
cp .env.example .env
# 在 .env 中配置 DASHSCOPE_API_KEY 等必要服务
./setup.sh full
./run.sh full
```

首次启动需参考 `.env.example` 配置平台级管理员环境变量后登录（完整多租户隔离能力）。

## 🔒 安全与合规

|------|---------|
